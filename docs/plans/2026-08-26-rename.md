# Rename: `omniscribe` → `panoscribe`

Tier: T4 (touches every module, every test import, every env var, the repo name)

## Why

`pip install omniscribe` installs **a different project** — *SoberMind Offline Session
Transcriber* (v0.0.5, uploaded 2026-05-30, five releases). It is also a Whisper-based
transcription tool, which makes the collision worse: a user may not notice they got the
wrong software. `README.md:36` documents that command today, so the published install
instructions are actively wrong.

The name cannot be reclaimed, so the project moves.

## Name selection — and why not `dualscribe`

`dualscribe` was the first choice and was **rejected during verification**:

- **IDEAL® DualScribe™** — an active trademark (fiber-optic scribing tools, IDEAL
  Industries).
- **Dualscribe Limited** — an active UK company (Fareham, Hampshire, #17289399).
- `dualscribe.com` registered 2025-10-06 via GoDaddy on AWS nameservers, serving nothing —
  consistent with the company above holding it.

Different trademark class to software, so use would probably not infringe — but "probably"
is not a foundation for a project name, and the `.com` is gone regardless.

**`panoscribe` was chosen instead.** *pan-* means *all*, the same semantics as *omni-*, so
it preserves the meaning of the original name and stays in the `-scribe` family.

## Scope: full rename

Everything. No half-measures, no permanent `pip install panoscribe` / `import omniscribe`
mismatch:

1. **Distribution** — `[project].name`, `[project.scripts]` console script, `Homepage` /
   `Repository` / `Changelog` URLs in `pyproject.toml`. Regenerate `uv.lock`.
2. **Import package** — `src/omniscribe/` → `src/panoscribe/` (use `git mv` to preserve
   history), and every `import omniscribe` / `from omniscribe...` across `src/`, `tests/`
   and `scripts/`.
3. **Env prefix** — `OMNI_*` → `PANO_*`. `env_prefix` in `config.py:47-51`, plus every
   `OMNI_` occurrence in tests, docs and examples.
4. **CLI command** — `omniscribe` → `panoscribe`.
5. **Tooling** — `--cov=omniscribe` in `.github/workflows/ci.yml` and `hooks/run-gate.sh`;
   `[tool.coverage.run] source`; any path in `scripts/`.
6. **Docker** — image tag and any in-image paths in `Dockerfile`, `README.md`,
   `PROJECT_CONTEXT.md`.
7. **Package metadata read at runtime** — the `/healthz` endpoint resolves the installed
   version via package name; it must look up `panoscribe`.
8. **Repo** — rename `dagonet/OmniScribe` → `dagonet/panoscribe` on GitHub, then update
   `git remote` and every hard-coded `dagonet/OmniScribe` URL in docs.

**This is a breaking change for anyone running from source.** Since nothing was ever
published, that set is small — but it includes the #77 reporter, so the changelog entry
must state the `OMNI_*` → `PANO_*` migration explicitly.

### Do not touch

`CHANGELOG.md` history and `docs/plans/*.md` are historical records. Rewriting them would
falsify what was true at the time. Only the new changelog entry is added.

## README must explain the rename

Add a short, permanent section (not a transient banner) stating:

- The project was called **OmniScribe** and is now **panoscribe**.
- Why: the `omniscribe` name on PyPI belongs to an unrelated project, so this one could
  never be published under it — and `pip install omniscribe` gets you different software.
- What changed for users: the install command, the CLI command, and the `OMNI_*` env vars
  are now `PANO_*`.
- That the GitHub URL redirects, so old links keep working.

Keep it factual. No apology, no marketing.
